## 5. Understanding GET by ID: Retrieve One Specific Object

Ravi Sir:

"Now suppose the customer wants only policy number 2. Should we return the entire collection?"

Student: No, sir. We should search for the specific policy.

### API endpoint

http

```
GET /api/policies/2
```

### Express route

JavaScript

```
app.get("/api/policies/:id", (req, res) => {

    const id = Number(req.params.id);

    const policy = policies.find(p => p.id === id);

    if (!policy) {
        return res.status(404).json({
            message: "Policy not found"
        });
    }

    res.status(200).json(policy);
});
```

### Understanding the flow

Request: `/api/policies/2`

Extract `req.params.id`

Route parameter = "2"

Convert to number

Number("2") → 2

Search array using `find()`

Found? Return policy : 404

### Important JavaScript concepts

`req.params.id`

Extracts the route parameter from the URL.

`Number()`

Converts the parameter string into a number.

`find()`

Returns the first matching object, or `undefined` if no match exists.

Strict equality (`===`)

Compares values without automatically converting their types.

### Understanding the POST operation

The server must:

1. Receive the HTTP request.

2. Extract the submitted JSON data.

3. Create or accept a policy object.

4. Insert the object into the collection.

5. Return an appropriate response.

### The JavaScript `push()` function

JavaScript

```
policies.push(newPolicy);
```

Ravi Sir:

"Students, what does push do?"

Students: It adds an element to the array.

Ravi Sir: "Exactly. Here, we are adding a new policy object to our existing policy collection."

### Complete POST implementation

JavaScript

```
app.post("/api/policies", (req, res) => {

    const newPolicy = req.body;

    policies.push(newPolicy);

    res.status(201).json({
        message: "Policy created successfully",
        policy: newPolicy
    });
});
```

For this initial classroom exercise, the request supplies the object directly. In a production API, the server should validate the fields and generate a unique ID rather than trusting a client-supplied ID.

## 7. Debugging Exercise: Why Is `req.body` Undefined?

This was one of the important debugging moments in the classroom.

Ravi Sir:

"The code looks correct. The route is executing. But when I try to access the request body, I get `undefined`. What could be wrong?"

### The problem

JavaScript

```
app.post("/api/policies", (req, res) => {

    const newPolicy = req.body;

    console.log(newPolicy);

    policies.push(newPolicy);

    res.status(201).json(newPolicy);
});
```

If JSON parsing middleware has not been configured, Express may not populate `req.body` for this JSON request.

### The solution

Add this statement before the route handlers:

JavaScript

```
app.use(express.json());
```

### Corrected application structure

JavaScript

```
const express = require("express");

const app = express();

const PORT = 3000;

// Middleware
app.use(express.json());

// Routes
app.get("/api/policies", (req, res) => {
    res.status(200).json(policies);
});

app.post("/api/policies", (req, res) => {

    const newPolicy = req.body;

    policies.push(newPolicy);

    res.status(201).json(newPolicy);
});

app.listen(PORT, () => {
    console.log(`Server listening on port ${PORT}`);
});
```

### What is middleware?

Middleware is a function that participates in processing an HTTP request before the final response is sent.

`express.json()` parses incoming JSON request bodies and makes the parsed value available through `req.body`.

## Express Middleware Pipeline

Incoming HTTP Request

`express.json()` Middleware

Parses JSON request body

Express Route Handler

Accesses `req.body`

HTTP Response

Mentor's analogy:

"Think of middleware as a checkpoint. Before the request reaches your route handler, the middleware performs a required operation—in this case, parsing JSON."

### Important debugging lesson

When a value is unexpectedly `undefined`, do not immediately rewrite the entire application.

Inspect the data flow:

* Is the client sending the expected data?

* Is the request content type correct?

* Is the middleware configured?

* Is the route receiving the request?

* What does `console.log(req.body)` display?

## 8. Understanding PUT: Updating an Existing Policy

Ravi Sir:

"Now suppose a policy's maturity period changes from 10 years to 15 years. Should we create another policy?"

Student: No, sir. We should update the existing record.

### API endpoint

http

```
PUT /api/policies/1
```

### Request body

JSON

```
{
  "name": "Jeevan Labh",
  "description": "Updated life insurance policy",
  "maturity": "15 years"
}
```

### Implementation

JavaScript

```
app.put("/api/policies/:id", (req, res) => {

    const id = Number(req.params.id);

    const policy = policies.find(p => p.id === id);

    if (!policy) {
        return res.status(404).json({
            message: "Policy not found"
        });
    }

    policy.name = req.body.name;
    policy.description = req.body.description;
    policy.maturity = req.body.maturity;

    res.status(200).json({
        message: "Policy updated successfully",
        policy: policy
    });
});
```

### Understanding the update logic

The `find()` method locates the existing object.

Once the object is found, its properties are modified.

JavaScript

```
policy.maturity = req.body.maturity;
```

Because the object is already part of the array, modifying its properties updates the object held in that collection.

Mentor's explanation: The application is not replacing the entire array. It is modifying the matching object.

## 9. Understanding DELETE: Removing a Policy

Ravi Sir:

"Now suppose a policy has been discontinued and should be removed from our sample collection. What operation do we use?"

Students: DELETE!

### API endpoint

http

```
DELETE /api/policies/2
```

### Implementation

JavaScript

```
app.delete("/api/policies/:id", (req, res) => {

    const id = Number(req.params.id);

    const policy = policies.find(p => p.id === id);

    if (!policy) {
        return res.status(404).json({
            message: "Policy not found"
        });
    }

    policies = policies.filter(p => p.id !== id);

    res.status(200).json({
        message: "Policy deleted successfully"
    });
});
```

### Understanding `filter()`

JavaScript

```
policies = policies.filter(p => p.id !== id);
```

The `filter()` method creates a new array containing elements that satisfy the condition.

Here, we retain every policy whose ID does not match the requested ID.

## 12. Important Observation: Why Does Data Disappear After Restarting?

Ravi Sir:

"Suppose I create a new policy using Postman. It appears in the collection. Now I stop the server and start it again. Where did that policy go?"

Student: It is gone, sir.

Ravi Sir: "Why?"

Because our data is stored in a JavaScript array in application memory.

When the Node.js process stops, the in-memory state is lost.

### Current implementation

```

    |
    v

    v

```

### Future implementation

```

    |

    |

```

Mentor's message: We started with an array to understand CRUD operations. The next step is persistent storage and proper separation of application layers.
