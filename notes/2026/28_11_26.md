## **2. The problem: Why do we need asynchronous programming?**

Imagine a software application that performs the following operations:

- Read data from a database.
- Call an external REST API.
- Read a file from disk.
- Download a document.
- Send an email.
- Wait for a payment gateway response.

These operations take time. Suppose an application calls a remote API, and the server takes 3 seconds to respond.Should the entire application stop working for those 3 seconds?

**No!**

Other operations should continue while we wait for the response. This is the fundamental idea behind asynchronous programming.

## **3. Synchronous vs asynchronous programming**

### **Synchronous programming**

In synchronous execution, operations execute sequentially.

```
Operation 1
     |
     v
Operation 2
     |
     v
Operation 3
     |
     v
Operation 4
```

The next operation waits until the previous operation completes.

Example:

```
console.log("Step 1");
console.log("Step 2");
console.log("Step 3");
console.log("Step 4");
```

Output:

```
Step 1
Step 2
Step 3
Step 4
```

Every statement executes in sequence.

### **Asynchronous programming**

In asynchronous execution, a time-consuming operation can be initiated, and the program can continue executing other work while waiting for its completion.

```
Application
    |
    |---- Start API request
    |
    |---- Continue other work
    |
    |---- API response arrives
    |
    |---- Process response
```

This improves responsiveness and resource utilization.

## **4. Real-world analogy – Tea at a canteen**

Imagine a student entering a college canteen.

**Student:** Sir, one cup of tea please.

**Canteen worker:** It will take 3 minutes.

The student doesn't stop the entire canteen.

Instead:

1. The student places an order.
2. The canteen starts preparing tea.
3. The student waits for the order.
4. Other customers continue ordering.
5. Tea becomes ready.
6. The student receives tea.

This is asynchronous thinking.

In programming:

| Canteen         | Programming              |
| --------------- | ------------------------ |
| Tea order       | Function call            |
| Tea preparation | Asynchronous operation   |
| Waiting time    | I/O latency              |
| Tea ready       | Promise resolved         |
| Tea delivered   | Result received          |
| Other customers | Other program operations |

**Mentor message:**

> Waiting for a result does not mean the entire system must stop working.

# **5. Understanding Promise**

A Promise represents the eventual result of an asynchronous operation.When an asynchronous operation starts, the result may not be available immediately. Instead of returning the actual result, it returns a `Promise`. A Promise can be in three states:

**Pending**

Operation is still in progress.

**Fulfilled**

Operation completed successfully.

**Rejected**

Operation failed.

### **Promise lifecycle**

A Promise is a contract:

> I don't have the result right now, but I will provide the result later, or tell you why the operation failed.

# **6. Creating a Promise in TypeScript**

Let's simulate a server response.

```
function getData(): Promise<string> {

    return new Promise<string>((resolve, reject) => {

        setTimeout(() => {

            resolve("Data received from server");

        }, 3000);

    });
}
```

### **Understanding the code**

```
function getData(): Promise<string>
```

This function returns a Promise whose successful result is a string.

```
new Promise<string>((resolve, reject) => {
```

We create a Promise.

- `resolve()` indicates success.
- `reject()` indicates failure.

```
setTimeout(() => {
    resolve("Data received from server");
}, 3000);
```

This simulates a server taking 3 seconds to respond.

After 3 seconds, the Promise is fulfilled.

# **7. Consuming a Promise using&#x20;**`.then()`

Before learning `async` and `await`, understand how Promises are consumed.

```
function getData(): Promise<string> {

    return new Promise<string>((resolve) => {

        setTimeout(() => {
            resolve("Data received from server");
        }, 3000);

    });
}

getData().then((result) => {

    console.log(result);

});

console.log("Program continues...");
```

### **Output**

```
Program continues...
```

After 3 seconds:

```
Data received from server
```

### **What did we learn?**

The function `getData()` starts an asynchronous operation. The program does not wait synchronously for 3 seconds. When the Promise is fulfilled, the callback registered with `.then()` executes.

# **8. Introducing&#x20;**`async`

The `async` keyword is used to declare an asynchronous function.

```
async function getEmployee() {

    return "Ravi";
}
```

Although the function returns a string, the caller receives a Promise. Conceptually:

```
async function getEmployee(): Promise<string> {

    return "Ravi";
}
```

Equivalent Promise-based understanding:

```
function getEmployee(): Promise<string> {

    return Promise.resolve("Ravi");
}
```

### **Demonstration**

```
async function getEmployee(): Promise<string> {

    return "Ravi";
}

getEmployee().then((name) => {

    console.log(name);

});
```

Output:

```
Ravi
```

### **Mentor explanation**

When we mark a function with `async`, we tell JavaScript:

> This function operates in an asynchronous programming context and its return value will be represented through a Promise.

# **9. Introducing&#x20;**`await`

The `await` keyword is used to wait for a Promise's result inside an asynchronous function. Consider this code:

```
async function main(): Promise<void> {
    let result = await getData();
    console.log(result);
}
```

### **What happens?**

```
let result = await getData();
```

1. `getData()` returns a Promise.
2. The Promise is initially pending.
3. `await` pauses the continuation of `main()`.
4. JavaScript can continue executing other work.
5. When the Promise is fulfilled, the result is assigned to `result`.
6. The next statement executes.

**Important:** `await` does not block the entire JavaScript runtime. It suspends the execution of that async function while allowing other work to proceed.

# **10. Complete example – Using&#x20;**`async`**&#x20;and&#x20;**`await`

```
function getData(): Promise<string> {

    return new Promise<string>((resolve) => {

        setTimeout(() => {

            resolve("Data received from server");

        }, 3000);

    });
}

async function main(): Promise<void> {

    console.log("Request started");
    let result = await getData();
    console.log(result);
    console.log("Request completed");
}

main();

console.log("Main program continues...");
```

### **Expected output**

```
Request started
Main program continues...
```

After 3 seconds:

```
Data received from server
Request completed
```

### **Execution timeline**

Time 0 seconds

`main()` begins → Request started → `await getData()`

Time 0 seconds

`main()` suspends → outside code executes → Main program continues!

Time 3 seconds

Promise resolves → `result` receives data → Request completed

# **11. Real-world example – Calling REST API**

A developer rarely creates artificial Promises using `setTimeout`.

In real applications, we use asynchronous APIs such as:

- `fetch()`
- Database APIs
- File system APIs
- HTTP clients
- Payment APIs

Let's fetch data from an external API.

```
async function getProducts(): Promise<void> {

    try {

        const response = await fetch("https://jsonplaceholder.typicode.com/posts" );
        const products = await response.json();
        console.log(products);

    }
    catch (error) {
        console.log("Error occurred:", error);
    }
}

getProducts();

console.log("Application started");
```

### **Execution steps**

**Step 1: Initiate HTTP request**

```
const response = await fetch(url);
```

`fetch()` returns a Promise.

We await the HTTP response.

**Step 2: Read response body**

```
const products = await response.json();
```

JSON parsing of the response body is also asynchronous, returning a Promise.

**Step 3: Display the result**

```
console.log(products);
```

After the response body is available, we display the result.

**Step 4: Handle exceptions**

```
catch (error) {
    console.log("Error occurred:", error);
}
```

If the request or body processing throws an error, we catch it. Note: `fetch()` does not automatically throw for HTTP statuses such as 404 or 500. We should check `response.ok` as well.

## **12. Improving API error handling**

In professional development, we should check HTTP status codes before reading the response.

```
async function getProducts(): Promise<void> {

    try {
        const response = await fetch( "https://jsonplaceholder.typicode.com/posts" );

        if (!response.ok) {
            throw new Error(`HTTP Error: ${response.status}`);
        }

        const products = await response.json();
        console.log(products);
    }
    catch (error) {
        console.error("Unable to fetch products:", error);
    }
}

getProducts();
```

### **Why check&#x20;**`response.ok`**?**

A server might return:

```
200 OK
```

or

```
404 Not Found
```

or

```
500 Internal Server Error
```

A `fetch()` request can still fulfill its Promise for HTTP errors such as 404 and 500. Therefore, we explicitly check `response.ok`.

## **13. Async programming with Employee class**

Now let's apply this concept to object-oriented programming. Imagine an application that fetches employee information from a remote server.

### **Employee model**

```
class Employee {

    public empId: number;
    public name: string;
    public department: string;
    public salary: number;

    constructor(id: number, nm: string, dept: string, sal: number ) {

        this.empId = id;
        this.name = nm;
        this.department = dept;
        this.salary = sal;
    }

    public display(): void {
        console.log("Employee ID:", this.empId);
        console.log("Name:", this.name);
        console.log("Department:", this.department);
        console.log("Salary:", this.salary);
    }
}
```

### **Employee service**

```
class EmployeeService {

    public async getEmployee(): Promise<Employee> {
        return new Promise<Employee>((resolve) => {

            setTimeout(() => {
                const employee = new Employee( 101,"Ravi","Engineering",75000);
                resolve(employee);
            }, 3000);
        });
    }
}
```

### **Application**

```
async function main(): Promise<void> {

    const service = new EmployeeService();
    console.log("Fetching employee information...");
    const employee = await service.getEmployee();
    employee.display();
    console.log("Employee information received.");
}

main();

console.log("Application is running...");
```

### **Output**

```
Fetching employee information...
Application is running...
```

After 3 seconds:

```
Employee ID: 101
Name: Ravi
Department: Engineering
Salary: 75000
Employee information received.
```

**Mentor message:** The object-oriented design doesn't change because the operation is asynchronous. We still use classes, objects, methods, abstraction and encapsulation. The difference is that the result is available in the future.

## **14. Sequential vs parallel asynchronous operations**

This is an important concept for software engineers.

Suppose an application needs to fetch:

- Employee information
- Department information
- Product information

Each API takes 3 seconds.

### **Approach 1: Sequential execution**

```
async function main(): Promise<void> {

    const employee = await getEmployee();
    const department = await getDepartment();
    const products = await getProducts();

    console.log(employee);
    console.log(department);
    console.log(products);
}
```

Execution:

```
Employee API       3 seconds
Department API     3 seconds
Products API       3 seconds
--------------------------
Total              9 seconds
```

Each operation waits for the previous one to complete.

### **Approach 2: Parallel execution**

```
async function main(): Promise<void> {

    const employeePromise = getEmployee();
    const departmentPromise = getDepartment();
    const productsPromise = getProducts();

    const employee = await employeePromise;
    const department = await departmentPromise;
    const products = await productsPromise;

    console.log(employee);
    console.log(department);
    console.log(products);
}
```

All three operations start before we await their results. Total execution time is approximately 3 seconds if each operation takes 3 seconds and their durations overlap.

### **Better approach:&#x20;**`Promise.all()`

```
async function main(): Promise<void> {

    const [employee, department, products] =
        await Promise.all([
            getEmployee(),
            getDepartment(),
            getProducts()
        ]);

    console.log(employee);
    console.log(department);
    console.log(products);
}
```

`Promise.all()` waits until all supplied Promises fulfill.


| Approach                   | Approximate time |
| -------------------------- | ---------------- |
| Sequential `await`         | 9 seconds        |
| Concurrent `Promise.all()` | 3 seconds        |

Engineering insight: When operations are independent, concurrent execution can improve performance. When the next operation depends on the previous result, sequential execution is necessary.

## **15. Common mistakes students make**

### **Mistake 1 – Forgetting&#x20;**`await`

```
async function main() {

    const result = getData();
    console.log(result);
}
```

Output may be:

```
Promise { <pending> }
```

Why? Because the variable `result` contains the Promise, not the actual resolved data. Correct:

```
async function main() {

    const result = await getData();
    console.log(result);
}
```

### **Mistake 2 – Using&#x20;**`await`**&#x20;outside an async function**

```
const result = await getData();
```

In traditional scripts, `await` must be inside an async function. Modern JavaScript supports top-level `await` in ES modules, but for our beginner exercises, we will use `async function main()`.

### **Mistake 3 – Assuming&#x20;**`async`**&#x20;makes everything faster**

```
async function calculate(): Promise<number> {
    return 10 + 20;
}
```

This does not make the calculation faster.

`async` provides a Promise-based return contract. Asynchronous programming is especially useful for I/O-bound work, such as network requests, files and database operations.

### **Mistake 4 – Ignoring errors**

```
async function main() {
    const result = await getData();
    console.log(result);
}
```

If `getData()` rejects, the error may become an unhandled rejection.

Correct:

```
async function main(): Promise<void> {

    try {
        const result = await getData();
        console.log(result);
    }
    catch (error) {
        console.error("Operation failed:", error);

    }
}
```

## **18. Summary – Mental model**

## **Promise → async → await**

**Promise**

Represents a result that will be available in the future.

**async**

Declares an asynchronous function and makes its return value Promise-based.

**await**

Suspends the continuation of the async function until the Promise settles.

```
async function main(): Promise<void> {
    const result = await getData();
    console.log(result);
}
```

### **Transflower mentor's closing message**

> A software application doesn't spend its life calculating. Most of the time, it waits — for a database, network, file, user or another service.
>
> A good software engineer understands how to manage this waiting time efficiently.
>
> `async` and `await` make asynchronous programming easier to read, but underneath them, the Promise mechanism and JavaScript's event loop continue to manage execution.

**Remember:** Don't confuse waiting for an operation with blocking the application. A well-designed application continues serving other work while it waits for the result of an external operation.
