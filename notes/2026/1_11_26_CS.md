# Playwright Browser Automation Testing for C# and ASP.NET Core Developers

Transflower TAP – Practical SDET Learning Module

The objective is to help C# developers understand browser automation testing using Playwright with TypeScript, while testing real-world ASP.NET Core MVC and Web API applications.

A C# developer does not need to abandon .NET to learn Playwright. Playwright supports multiple programming languages, including .NET (C#) and TypeScript.

We will use Playwright + C# + NUnit/xUnit for the primary examples.

- Business services: Execute business rules.
- Database: Stores application information.

## 4. First browser automation test using C# and NUnit

Create `HomePageTests.cs`.

```
using Microsoft.Playwright;
using NUnit.Framework;

namespace TFLPlaywrightTests;

public class HomePageTests
{
    private IPlaywright playwright = null!;
    private IBrowser browser = null!;
    private IPage page = null!;

    [SetUp]
    public async Task Setup()
    {
        playwright = await Playwright.CreateAsync();

        browser = await playwright.Chromium.LaunchAsync(
            new BrowserTypeLaunchOptions
            {
                Headless = false
            });

        page = await browser.NewPageAsync();
    }

    [Test]
    public async Task VerifyHomePage()
    {
        await page.GotoAsync("https://example.com");

        string title = await page.TitleAsync();

        Assert.That(title, Is.EqualTo("Example Domain"));

        await page.ScreenshotAsync(
            new PageScreenshotOptions
            {
                Path = "homepage.png"
            });
    }

    [TearDown]
    public async Task Cleanup()
    {
        await browser.CloseAsync();
        playwright.Dispose();
    }
}
```

Execute:

```
dotnet test
```

This is your first browser automation test using C#.

## 6. Practical lab – ASP.NET Core MVC Login Testing

Assume we have an ASP.NET Core MVC application.

Login page:

```
http://localhost:5000/Account/Login
```

HTML elements:

```
Username
Password
Remember Me
Login Button
```

Create `LoginTests.cs`.

```
using Microsoft.Playwright;
using NUnit.Framework;

namespace TFLPlaywrightTests;

public class LoginTests
{
    private IPlaywright playwright = null!;
    private IBrowser browser = null!;
    private IPage page = null!;

    [SetUp]
    public async Task Setup()
    {
        playwright = await Playwright.CreateAsync();

        browser = await playwright.Chromium.LaunchAsync(
            new BrowserTypeLaunchOptions
            {
                Headless = false
            });

        page = await browser.NewPageAsync();
    }

    [Test]
    public async Task ValidLoginTest()
    {
        await page.GotoAsync(
            "http://localhost:5000/Account/Login");

        await page.GetByLabel("Username")
                  .FillAsync("student01");

        await page.GetByLabel("Password")
                  .FillAsync("Test@123");

        await page.GetByRole(
            AriaRole.Button,
            new() { Name = "Login" })
            .ClickAsync();

        await page.WaitForURLAsync("**/Dashboard");

        var heading = page.GetByText("Student Dashboard");

        Assert.That(
            await heading.IsVisibleAsync(),
            Is.True);
    }
}
```

Note: The application must expose the corresponding labels, route and dashboard heading. Adapt the URL and selectors to your MVC application.

## 7. API testing – ASP.NET Core Web API

Playwright can test APIs independently of browser UI.

Suppose your application exposes:

```
GET    /api/products
GET    /api/products/101
POST   /api/products
PUT    /api/products/101
DELETE /api/products/101
```

Example NUnit API test:

```
using Microsoft.Playwright;
using NUnit.Framework;

namespace TFLPlaywrightTests;

public class ProductApiTests
{
    private IPlaywright playwright = null!;
    private IAPIRequestContext request = null!;

    [SetUp]
    public async Task Setup()
    {
        playwright = await Playwright.CreateAsync();

        request = await playwright.APIRequest
            .NewContextAsync(
                new APIRequestNewContextOptions
                {
                    BaseURL = "http://localhost:5000"
                });
    }

    [Test]
    public async Task GetProductsTest()
    {
        var response = await request.GetAsync(
            "/api/products");

        Assert.That(
            response.Status,
            Is.EqualTo(200));

        string json = await response.TextAsync();

        Assert.That(json, Is.Not.Empty);
    }

    [TearDown]
    public async Task Cleanup()
    {
        await request.DisposeAsync();
        playwright.Dispose();
    }
}
```

## 8. UI testing vs API testing vs Unit testing

| Testing type        | Technology                                      | What do we test?                |
| ------------------- | ----------------------------------------------- | ------------------------------- |
| Unit testing        | xUnit / NUnit                                   | Individual methods              |
| Integration testing | ASP.NET Core TestServer / WebApplicationFactory | Application components together |
| API testing         | Playwright API / HttpClient                     | HTTP endpoints                  |
| Browser automation  | Playwright                                      | Actual browser and UI           |
| End-to-end testing  | Playwright                                      | Complete business workflow      |

An important distinction: API testing through Playwright verifies HTTP behavior. It does not automatically verify database persistence or all backend integrations. Those require additional integration or database-level assertions.

## 10. SDET learning progression for C# developers

## From C# Developer to Automation Engineer

1. Level 1 – C# Testing Fundamentals

   NUnit, xUnit, assertions, test fixtures, setup and teardown.
2. Level 2 – Browser Automation

   Playwright, locators, actions, navigation and assertions.
3. Level 3 – Functional Testing

   Login, registration, CRUD, forms and business workflows.
4. Level 4 – API and Integration Testing

   HTTP methods, authentication, JSON, Web API and database validation.
5. Level 5 – Automation Engineering

   Page Object Model, reusable utilities, data-driven testing.
6. Level 6 – Enterprise Automation

   CI/CD, Docker, parallel execution, reporting and observability.

## Mentor's perspective

A beginner tester asks:

"Does the Login button work?"

A good automation engineer asks:

"Does login work with valid credentials, invalid credentials, expired sessions, and network failures?"

A senior SDET asks:

"Can the entire authentication workflow be trusted under production conditions?"

The difference is not the programming language. The difference is engineering thinking.

My recommendation for TAP: teach C# developers NUnit/xUnit fundamentals first, then Playwright with C#, then API and integration testing. This allows students to build on their existing .NET knowledge instead of learning another programming language just to start automation testing.
