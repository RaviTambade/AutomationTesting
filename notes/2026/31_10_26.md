# Playwright – Most Commonly Used Testing Scenarios and Functions

For Transflower students learning Software Testing / SDET, I recommend teaching Playwright through real-world application testing scenarios, rather than memorizing Playwright functions. Let's use a practical approach with Playwright + JavaScript + Node.js.

We will cover:

1. Browser and page management
2. Locators and element identification
3. User interactions
4. Assertions and validations
5. Forms and input controls
6. Navigation and page handling
7. Screenshots and videos
8. API testing
9. Authentication and session testing
10. Real-world end-to-end test scenarios

## 2. Commonly used Playwright functions

### A. Browser and page management

| Function               | Purpose                         |
| ---------------------- | ------------------------------- |
| `chromium.launch()`    | Launch Chromium browser         |
| `browser.newPage()`    | Create a new page               |
| `browser.newContext()` | Create isolated browser context |
| `context.newPage()`    | Open new page in context        |
| `page.goto()`          | Navigate to URL                 |
| `page.url()`           | Get current URL                 |
| `page.title()`         | Get page title                  |
| `page.close()`         | Close page                      |
| `browser.close()`      | Close browser                   |

Example:

```

const { chromium } = require('playwright');

(async () => {
    const browser = await chromium.launch({ headless: false});

    const page = await browser.newPage();

    await page.goto('https://example.com');

    console.log(await page.title());
    console.log(page.url());

    await browser.close();
})();

```

### B. Locators – Finding HTML elements

Locators are the foundation of browser automation.

| Function                  | Purpose                       |
| ------------------------- | ----------------------------- |
| `page.locator()`          | Find elements using CSS/XPath |
| `page.getByRole()`        | Find by accessible role       |
| `page.getByText()`        | Find by visible text          |
| `page.getByLabel()`       | Find form controls by label   |
| `page.getByPlaceholder()` | Find using placeholder        |
| `page.getByTestId()`      | Find using test ID            |
| `page.getByAltText()`     | Find images using alt text    |
| `locator.first()`         | Get first matching element    |
| `locator.last()`          | Get last matching element     |
| `locator.nth()`           | Get element by index          |
| `locator.filter()`        | Filter matching elements      |
| `locator.count()`         | Count matching elements       |

Example:

```

const username = page.locator('#username');
const password = page.locator('#password');

const loginButton = page.getByRole('button', { name: 'Login'});
const heading = page.getByText('Welcome');
console.log(await loginButton.count());

```

Mentor tip: Prefer `getByRole()`, `getByLabel()`, and `getByTestId()` over brittle XPath expressions. They generally produce more maintainable tests.

| Function                  | Purpose                          |
| ------------------------- | -------------------------------- |
| `locator.click()`         | Click button or link             |
| `locator.dblclick()`      | Double-click                     |
| `locator.fill()`          | Enter text into input            |
| `locator.clear()`         | Clear input                      |
| `locator.press()`         | Press keyboard key               |
| `locator.type()`          | Type text character by character |
| `locator.check()`         | Select checkbox                  |
| `locator.uncheck()`       | Deselect checkbox                |
| `locator.selectOption()`  | Select dropdown option           |
| `locator.hover()`         | Mouse hover                      |
| `locator.focus()`         | Focus element                    |
| `locator.blur()`          | Remove focus                     |
| `locator.tap()`           | Touch/tap interaction            |
| `locator.setInputFiles()` | Upload file                      |

Example:

```
await page.locator('#username').fill('student01');

await page.getByRole('button', { name: 'Login'}).click();
await page.locator('#rememberMe').check();

```

### D. Assertion functions

Assertions verify whether the application behaves as expected.

| Assertion                    | Purpose                 |
| ---------------------------- | ----------------------- |
| `expect().toBeVisible()`     | Element is visible      |
| `expect().toBeHidden()`      | Element is hidden       |
| `expect().toHaveText()`      | Verify text             |
| `expect().toContainText()`   | Verify partial text     |
| `expect().toHaveValue()`     | Verify input value      |
| `expect().toBeEnabled()`     | Verify enabled control  |
| `expect().toBeDisabled()`    | Verify disabled control |
| `expect().toBeChecked()`     | Verify checkbox         |
| `expect().toHaveURL()`       | Verify URL              |
| `expect().toHaveTitle()`     | Verify page title       |
| `expect().toHaveCount()`     | Verify element count    |
| `expect().toHaveAttribute()` | Verify HTML attribute   |
| `expect().toHaveClass()`     | Verify CSS class        |

Example:

```
const { test, expect } = require('@playwright/test');

test('Verify login page', async ({ page }) => {

    await page.goto('http://localhost:5173');
    await expect(page).toHaveTitle(/Assessment/);
    await expect(page.getByRole('heading', { name: 'Welcome' })).toBeVisible();
    await expect(page.getByRole('button', { name: 'Login' })).toBeEnabled();

});
```

### F. Wait and synchronization functions

Playwright automatically waits for many element actions and assertions. Avoid unnecessary fixed delays.

| Function                        | Purpose                            |
| ------------------------------- | ---------------------------------- |
| `locator.waitFor()`             | Wait for element state             |
| `page.waitForURL()`             | Wait for URL change                |
| `page.waitForLoadState()`       | Wait for load state                |
| `page.waitForResponse()`        | Wait for API response              |
| `page.waitForRequest()`         | Wait for network request           |
| `page.waitForEvent()`           | Wait for browser event             |
| `expect(locator).toBeVisible()` | Auto-retrying visibility assertion |

Example:

```
await page.getByRole('button', { name: 'Login'}).click();
await page.waitForURL('**/dashboard');
await expect( page.getByText('Student Dashboard')).toBeVisible();
```

Avoid this pattern unless there is a genuine reason:

```
await page.waitForTimeout(5000);
```

A fixed delay makes tests slower and less reliable.

### G. Screenshots, videos and reports

| Function / Configuration        | Purpose                     |
| ------------------------------- | --------------------------- |
| `page.screenshot()`             | Capture screenshot          |
| `fullPage: true`                | Full-page screenshot        |
| `page.video()`                  | Access recorded video       |
| `screenshot: 'only-on-failure'` | Capture failure screenshots |
| `video: 'retain-on-failure'`    | Retain failed-test videos   |
| `trace: 'retain-on-failure'`    | Record execution trace      |
| `--reporter=html`               | Generate HTML report        |

Example:

```
await page.screenshot({ path: 'screenshots/dashboard.png',fullPage: true});
```

### H. Browser context and session management

| Function                 | Purpose                   |
| ------------------------ | ------------------------- |
| `browser.newContext()`   | Create isolated session   |
| `context.newPage()`      | Open page in session      |
| `context.cookies()`      | Read cookies              |
| `context.addCookies()`   | Add cookies               |
| `context.clearCookies()` | Clear cookies             |
| `context.storageState()` | Save authentication state |
| `page.reload()`          | Reload page               |
| `page.goBack()`          | Navigate backward         |
| `page.goForward()`       | Navigate forward          |

Example:

```
const context = await browser.newContext();
const page = await context.newPage();
await page.goto('http://localhost:5173');
await page.reload();
await page.goBack();
await page.goForward();
```

### I. Dialog, popup and file handling

| Function                        | Purpose                       |
| ------------------------------- | ----------------------------- |
| `page.on('dialog')`             | Handle alert, confirm, prompt |
| `dialog.accept()`               | Accept dialog                 |
| `dialog.dismiss()`              | Dismiss dialog                |
| `page.waitForEvent('popup')`    | Handle popup                  |
| `page.waitForEvent('download')` | Handle downloads              |
| `locator.setInputFiles()`       | Upload files                  |
| `download.saveAs()`             | Save downloaded file          |

Example – JavaScript alert:

```
page.on('dialog', async dialog => {
    console.log(dialog.message());
    await dialog.accept();
});

await page.getByRole('button', { name: 'Delete'}).click();
```

### J. API testing functions

Playwright can test REST APIs without opening a browser.

| Function             | Purpose               |
| -------------------- | --------------------- |
| `request.get()`      | HTTP GET              |
| `request.post()`     | HTTP POST             |
| `request.put()`      | HTTP PUT              |
| `request.patch()`    | HTTP PATCH            |
| `request.delete()`   | HTTP DELETE           |
| `response.status()`  | HTTP status           |
| `response.json()`    | Read JSON             |
| `response.headers()` | Read response headers |

Example:

```
const { test, expect } = require('@playwright/test');

test('Get assessment list', async ({ request }) => {
    const response = await request.get('http://localhost:5000/api/assessments');
    expect(response.status()).toBe(200);
    const data = await response.json();
    console.log(data);
});
```

### Scenario 1: Student login

```
test('Student login', async ({ page }) => {

    await page.goto('http://localhost:5173/login');
    await page.getByLabel('Username').fill('student01');
    await page.getByLabel('Password').fill('Test@123');
    await page.getByRole('button', {   name: 'Login' }).click();

    await expect(page).toHaveURL(/dashboard/);
    await expect(page.getByText('Student Dashboard')).toBeVisible();

});
```

### Scenario 2: View assigned assessments

```
test('Display assigned assessments', async ({ page }) => {

    await page.goto('http://localhost:5173/assessments');
    const assessments = page.locator('.assessment-card');
    await expect(assessments).toHaveCount(3);
    await expect(page.getByText('Python Fundamentals')).toBeVisible();

});
```

### Scenario 3: Answer MCQ questions

```
test('Select MCQ answer', async ({ page }) => {
    await page.goto('http://localhost:5173/assessment/101');
    await page.getByLabel('Option B').check();
    await expect(  page.getByLabel('Option B')).toBeChecked();
    await page.getByRole('button', { name: 'Next' }).click();
    await expect(page.getByText('Question 2')).toBeVisible();
});
```

### Scenario 4: Submit assessment

```
test('Submit assessment', async ({ page }) => {
    await page.goto('http://localhost:5173/assessment/101');
    await page.getByRole('button', { name: 'Submit Assessment' }).click();
    await expect(page.getByText('Confirm Submission')).toBeVisible();
    await page.getByRole('button', { name: 'Confirm'}).click();
    await expect(page.getByText('Assessment Submitted')).toBeVisible();
});
```

### Scenario 5: Verify assessment result API

```
test('Verify student assessment result', async ({ request }) => {

    const response = await request.get('http://localhost:5000/api/assessments/101/result' );
    expect(response.status()).toBe(200);
    const result = await response.json();
    expect(result).toHaveProperty('totalQuestions');
    expect(result).toHaveProperty('correctAnswers');
    expect(result).toHaveProperty('score');
    expect(result.score).toBeGreaterThanOrEqual(0);
    expect(result.score).toBeLessThanOrEqual(100);
});
```

Note: These examples assume corresponding routes, labels, test IDs, and API response properties exist in your application. Adjust them to match your implementation.

## 5. Advanced Playwright capabilities

Once students understand basic automation, introduce these capabilities:

| Capability               | Playwright API                       |
| ------------------------ | ------------------------------------ |
| Network interception     | `page.route()`                       |
| Mock API response        | `route.fulfill()`                    |
| Continue network request | `route.continue()`                   |
| Abort network request    | `route.abort()`                      |
| Multiple tabs            | `context.newPage()`                  |
| Mobile emulation         | `browser.newContext({ ...devices })` |
| Geolocation              | `geolocation` context option         |
| Permissions              | `context.grantPermissions()`         |
| Accessibility snapshots  | `locator.ariaSnapshot()`             |
| Parallel execution       | `fullyParallel`                      |
| Test grouping            | `test.describe()`                    |
| Test setup               | `test.beforeEach()`                  |
| Test cleanup             | `test.afterEach()`                   |
| Retry failed tests       | `retries` configuration              |
| Parameterized tests      | `test()` with data iteration         |

Example – Mock an API response:

```
test('Mock assessment API', async ({ page }) => {

    await page.route('**/api/assessments', async route => {

        await route.fulfill({
            status: 200,
            contentType: 'application/json',
            body: JSON.stringify([
                {
                    id: 1,
                    title: 'Python Fundamentals',
                    duration: 30
                }
            ])
        });
    });

    await page.goto('http://localhost:5173/assessments');
    await expect( page.getByText('Python Fundamentals')).toBeVisible();

});
```

## 6. Recommended Playwright project structure

For a professional automation testing project:

```
playwright-testing/
│
├── tests/
│   ├── login.spec.js
│   ├── registration.spec.js
│   ├── dashboard.spec.js
│   ├── assessment.spec.js
│   ├── result.spec.js
│   └── api/
│       ├── users.api.spec.js
│       └── assessment.api.spec.js
│
├── pages/
│   ├── LoginPage.js
│   ├── DashboardPage.js
│   └── AssessmentPage.js
│
├── fixtures/
│   └── testData.js
│
├── test-results/
├── playwright-report/
│
├── playwright.config.js
└── package.json
```

This structure introduces the Page Object Model (POM), reusable functions, test data management and separation of test logic from UI locators.

## 7. Installation and execution commands

For a new JavaScript Playwright project:

```
mkdir playwright-testing

cd playwright-testing

npm init -y

npm install -D @playwright/test

npx playwright install chromium
```

Create sample tests:

```
npx playwright test --init
```

Run tests:

```
# Run all tests
npx playwright test

# Run only Chromium
npx playwright test --project=chromium

# Run specific test
npx playwright test tests/login.spec.js

# Run with visible browser
npx playwright test --headed

# Run in debug mode
npx playwright test --debug

# Run with HTML report
npx playwright test --reporter=html

# Open HTML report
npx playwright show-report
```

## 9. Mentor's perspective: How to become an SDET

## SDET skill progression

1. Level 1 – Automation Fundamentals

   Locators, selectors, click, fill, assertions, navigation.
2. Level 2 – Functional Testing

   Login, registration, forms, CRUD, validation and workflows.
3. Level 3 – Automation Engineering

   POM, fixtures, reusable utilities, data-driven testing.
4. Level 4 – API & Integration Testing

   REST API, HTTP methods, database validation, network mocking.
5. Level 5 – Enterprise Test Automation

   CI/CD, Docker, parallel execution, reporting, observability.

My mentoring principle:

A beginner tester asks: "Does the Login button work?"

A good automation engineer asks: "Does login work for valid credentials, invalid credentials, expired sessions, concurrent users, and network failures?"

A senior SDET asks: "Can the entire authentication workflow be trusted under production conditions?"

That is the difference between learning Playwright functions and developing engineering skills.
