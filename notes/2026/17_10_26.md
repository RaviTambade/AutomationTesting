# Git & GitHub 
 
When manual testers start learning automation testing with Python and Playwright, they need to learn one more essential skill: how to manage test scripts using Git and GitHub.

Think of a test automation project as a test laboratory:

- Local machine — your personal testing lab.
- Git — the lab's version history and change tracker.
- GitHub remote repository — the shared lab in the cloud.
- Commit — a saved checkpoint of your work.
- Push — sending your saved checkpoints to GitHub.

By the end of this lab, students will create a repository, clone it, add a test script, stage and commit the changes, and push them to their own GitHub account—all using the command line.

## Lab overview

Objective

Publish your first test automation script to GitHub using Git commands.

Prerequisites

Windows computer, internet access, a GitHub account, and Git installed.

Estimated duration

45–60 minutes for beginners.

Our practice project will be named `playwright-testing-lab`.

## Step 3 — Configure your Git identity

Git records the author name and email in each commit. Configure them before creating your first commit.

```
git config --global user.name "Your Full Name"

git config --global user.email "your-email@example.com"
```

Replace the example values with your own details. Use an email associated with your GitHub account if you want commits to be associated with that account.

Verify your configuration:

```
git config --global --list
```

You should see your configured name and email.

Mentor tip: Git identity and GitHub authentication are different. These commands identify the author of a commit; they do not sign you in to GitHub.

## Step 4 — Clone the remote repository to your computer

Go back to your GitHub repository page. Click Code → HTTPS, then copy the repository URL.

Open Git Bash and move to the folder where you want to keep your projects. For example:

```
cd /c/Users/YourWindowsUsername/Documents
```

Replace `YourWindowsUsername` with your Windows username.

Now clone the repository:

```
git clone https://github.com/YOUR-USERNAME/playwright-testing-lab.git
```

Replace `YOUR-USERNAME` with your GitHub username.

Enter the cloned folder:

```
cd playwright-testing-lab
```

Verify the remote connection:

```
git remote -v
```

Expected output:

```
origin  https://github.com/YOUR-USERNAME/playwright-testing-lab.git (fetch)
origin  https://github.com/YOUR-USERNAME/playwright-testing-lab.git (push)
```

`origin` is simply the conventional name Git gives the remote repository. Cloning creates a local working copy connected to the remote.&#x20;

## Step 5 — Add your first test automation content

Let's create a simple test case description before writing browser automation code.

In Git Bash, run:

```
notepad README.md
```

If Notepad asks whether you want to create a new file, select Yes.

Enter this content:

```

# Playwright Testing Lab

## Objective
Learn Git, GitHub, and browser automation testing.

## Test Scenario: Login Page

Test Case ID: TC_LOGIN_001

Test Case: Verify login page availability.

Precondition:
- Browser is installed.
- Test application URL is available.

Steps:
1. Open the browser.
2. Navigate to the login page.
3. Verify that the login page is displayed.

Expected Result:
The login page should load successfully.

## Learning Topics
- Git basics
- GitHub repositories
- Playwright with Python
- Browser automation

```

Save the file and close Notepad.

Check the contents of your working directory:

```
ls
```

You should see:

```
README.md
```

At this point, you have created a local file. It is not yet part of a commit and has not been uploaded to GitHub.

## Step 6 — Check the Git working tree

Run:

```
git status
```

You should see output similar to:

```
On branch main

Untracked files:
  README.md

nothing added to commit but untracked files present
```

The exact wording may differ slightly.

What does this mean?

- `README.md` exists locally.
- Git sees the file but is not yet tracking it.
- The file has not been staged.
- No commit has been created for this file.

This is your first opportunity to teach students the difference between a file existing on disk and Git tracking its changes.

## Step 7 — Stage the file

Now tell Git which changes you want included in the next commit.

```
git add README.md
```

Check the status again:

```
git status
```

Expected output:

```
Changes to be committed:
  new file: README.md
```

You can also stage all intended changes in the current directory with:

```
git add .
```

For beginners, I recommend `git add README.md` first because it makes the selected file explicit.

Remember: Staging does not upload anything to GitHub. It prepares selected changes for the next commit.

## Step 8 — Commit your changes

Create a commit with a meaningful message:

```
git commit -m "Add initial login test scenario"
```

Expected output will resemble:

```
[main abc1234] Add initial login test scenario
 1 file changed, ...
```

The short commit identifier will differ on your computer.

Check the commit history:

```
git log --oneline
```

You should see your new commit at the top.

A commit is a saved checkpoint in your local repository history. It is not yet necessarily present in the remote repository.

## Step 9 — Push your commit to GitHub

Now publish your local commit to the remote repository.

```
git push origin main
```

Here is what the command means:

| Command part | Meaning               |
| ------------ | --------------------- |
| `git push`   | Publish local commits |
| `origin`     | The remote repository |
| `main`       | The branch to publish |

Because you cloned an empty repository, the branch is normally `main`. If your repository uses a different branch name, use that branch instead.

If authentication is required, Git Credential Manager may open a browser sign-in flow. Complete the sign-in using your own GitHub account.

GitHub no longer accepts your normal account password as the password for Git operations over HTTPS. Use Git Credential Manager or GitHub CLI for authentication; a personal access token is another option when required. Never share a token with your instructor or classmates.&#x20;

After the push succeeds, open your GitHub repository in the browser and refresh the page. You should see `README.md` and your commit message.

## Step 10 — Verify the complete workflow

Run these commands:

```
git status
git log --oneline
git remote -v
```

A clean working tree should display a message similar to:

```
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
```

Congratulations! You have completed the full Git workflow.

## Step 11 — Common problems and solutions

| Problem                               | What to check                                                                                                        |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `git is not recognized`               | Install Git for Windows and reopen the terminal.                                                                     |
| `Repository not found`                | Check the repository URL, account permissions, and spelling.                                                         |
| `Authentication failed`               | Complete browser authentication through Git Credential Manager or configure another supported authentication method. |
| `nothing to commit`                   | Run `git status`; confirm you created or changed a file.                                                             |
| `src refspec main does not match any` | Confirm a commit exists and check the current branch with `git branch --show-current`.                               |
| `non-fast-forward`                    | The remote has commits you do not have locally. Inspect the remote history and synchronize before pushing.           |

Official reference: [GitHub documentation on remote repositories](https://docs.github.com/en/get-started/git-basics/about-remote-repositories?utm_source=chatgpt.com).
