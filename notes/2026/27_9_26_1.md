## 3. From CRUD Operations to Web APIs

Previously, we worked with arrays and JSON objects.

For example:

JavaScript

```
let students = [
    { id: 1, name: "Amit", course: "Java" },
    { id: 2, name: "Rutuja", course: "Python" }
];
```

We performed operations such as:

JavaScript

```
students.push(newStudent);
students.filter(student => student.id !== 1);
```

But there is a limitation.

The data exists inside the running program's memory.

If the application restarts, the in-memory data may be lost.

Real applications commonly persist data in databases or files.

### The evolution

Level 1 — In-memory programming

Variables, objects, arrays, functions

Level 2 — File-based persistence

JSON files, file operations

Level 3 — Database persistence

SQL, tables, queries, transactions

Level 4 — Web API

HTTP requests, routes, controllers, services

Level 5 — Distributed application

Multiple clients, servers, APIs, databases

### What is a Web API?

A Web API exposes application functionality through network-accessible endpoints, typically using HTTP.

For example, a Transflower student portal might expose:

http

```
GET    /api/students
GET    /api/students/101
POST   /api/students
PUT    /api/students/101
DELETE /api/students/101
```

The client does not need to know how the server internally implements student registration.

It only needs to understand the API contract.

Ravi Sir: "That is abstraction. We expose functionality while hiding internal implementation details."

## 4. Understanding Three-Tier Architecture

Imagine a student opens the Transflower portal and submits a registration form.

Where does the information go?

A typical application separates responsibilities into three logical tiers.

## Three-Tier Application Architecture

Presentation Tier

Browser · HTML · CSS · JavaScript · React

Displays forms and collects user input

HTTP Request / Response

Application / Business Logic Tier

Express · ASP.NET Core · Spring Boot · FastAPI

Validates requests and executes business rules

Database Queries / Results

Data Tier

MySQL · SQL Server · PostgreSQL

Stores and retrieves persistent information

### Student dialogue

Rutuja: Sir, can we write database queries directly inside the HTML page?

Ravi Sir: Technically, different architectures are possible, but in a typical web application, we separate these responsibilities.

The browser handles presentation. The server handles business logic. The database handles persistent storage.

Ankush: Sir, why do we separate them?

Ravi Sir: Because changes become easier to manage. We can change the user interface without rewriting business rules. We can change database implementation without necessarily changing the browser interface.

This separation also supports testing, maintenance, and team collaboration.

### Important distinction

Three-tier architecture describes logical responsibility separation. It does not necessarily mean three physical computers.

All three tiers might run on one machine during development, or they may be deployed across separate infrastructure in production.

### What is N-tier architecture?

When an application has additional logical layers or services beyond the traditional three tiers, it is often described as an N-tier architecture.

For example:

```
Presentation Layer
       |
Web/API Layer
       |
Business Logic Layer
       |
Data Access Layer
       |
Database Layer
```

Mentor's takeaway: Architecture is about organizing responsibilities and managing complexity—not simply drawing boxes.

## 6. Understanding HTTP and HTTPS

A browser and a web server need a communication protocol.

HTTP stands for Hypertext Transfer Protocol.

It defines how clients and servers exchange requests and responses.

### HTTP request-response cycle

Client / Browser

Requests student information

HTTP Request

Web Server / API

Processes request and executes logic

Database operations, if required

HTTP Response

Client / Browser

Displays returned information

### Example request

http

```
GET /api/students/101 HTTP/1.1
Host: portal.transflower.in
Accept: application/json
```

### Example response

http

```
HTTP/1.1 200 OK
Content-Type: application/json
```

JSON

```
{
  "id": 101,
  "name": "Rutuja",
  "course": "Python"
}
```

## 8. API Testing: Developer and Tester Collaboration

Ravi Sir:

"Now suppose the developer says, 'Sir, my API is working perfectly.'

Should the tester simply believe the developer?"

Students: No, sir!

Ravi Sir: Exactly. We need evidence.

Testing verifies whether the application behaves according to its requirements.

### API testing workflow

1. Understand the API requirement and contract.

2. Identify endpoints, request methods, parameters, headers, and body.

3. Prepare valid and invalid test data.

4. Send requests using an API testing tool.

5. Verify status codes, response body, headers, and response time.

6. Record failures and report reproducible defects.

## 11. AI-Assisted Automation Testing

Ravi Sir also discussed using AI tools such as ChatGPT or Claude to help generate test code.

AI can assist with:

* Generating test-case ideas

* Creating test-data variations

* Drafting unit-test structures

* Suggesting edge cases

* Explaining unfamiliar framework syntax

* Helping convert manual test cases into automation scripts

However, AI-generated tests must be reviewed and executed.

### Classroom example

Requirement:

> A student registration API must reject requests without an email address.

AI may generate a test structure:

JavaScript

```
describe("Student Registration API", () => {

    test("should reject missing email", async () => {

        const response = await request(app)
            .post("/api/students")
            .send({
                name: "Amit"
            });

        expect(response.status).toBe(400);

    });

});
```

The tester must verify that:

1. The endpoint is correct.

2. The request matches the API contract.

3. The expected status code matches the application's requirements.

4. The test actually fails when the validation is removed.

5. The test is stable and repeatable.

Mentor's message: AI can accelerate test creation, but test quality depends on understanding requirements, application behavior, and expected outcomes.

## 13. Classroom Discussion: What Does an Automation Test Engineer Need to Know?

Ravi Sir:

"Students, when you join a company, you may not get to choose the technology stack. The company may already be using Java, C#, Python, or JavaScript."

The important questions are:

* Can you understand the product?

* Can you convert requirements into test cases?

* Can you identify positive and negative scenarios?

* Can you automate repetitive testing?

* Can you debug test failures?

* Can you communicate defects clearly?

* Can you learn a new framework when required?

The programming language is important, but it is only one part of the engineering skill set.

## 14. Key Takeaways

## What We Learned Today

1. Web frameworks help developers build organized applications and APIs.

2. CRUD operations can evolve from in-memory collections to persistent database operations exposed through APIs.

3. Three-tier architecture separates presentation, business logic, and data responsibilities.

4. N-tier architecture organizes additional responsibilities across application layers.

5. HTTP enables request-response communication between clients and servers.

6. HTTPS uses TLS to secure communication.

7. Authentication and authorization solve different security problems.

8. Testing should cover individual components, integrations, APIs, UI, and deployed systems.

9. Automation testing concepts can transfer across programming languages and frameworks.

10. AI can assist with test generation, while engineers remain responsible for validation.
