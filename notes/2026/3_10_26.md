```text
 |-- Who are you?
 |
 v
Authorization
 |
 |-- What are you allowed to do?
 |
 v
Application
```

Testing engineers need to understand these flows because a test that ignores authentication may not represent the real application.
 

# Performance Testing

Then I ask the class:

> “Suppose tomorrow 50,000 users come to your application. What happens?”

A student says:

> “Sir, server will become slow.”

I ask:

**“How do you know?”**

Now we need performance testing and monitoring. We may measure things such as:

```text
Requests / Second
Response Time
CPU Utilization
Memory Usage
Error Rate
Throughput
Concurrent Users
```

Suppose traffic suddenly increases:

```text
              USERS
                |
                v
        +---------------+
        | Load Balancer |
        +---------------+
          /     |      \
         /      |       \
        v       v        v
     Server1 Server2  Server3
```

Now the automation/test engineer should understand the conversation happening between development, testing, and DevOps. The tester may not personally change the infrastructure. But the tester should be able to say:

> “Our monitoring shows that requests per second increased and response time has crossed the expected threshold.”

That is useful engineering information.
 

# VPN: Working From Anywhere

Then there is another part of modern software work. Your production environment may be inside a protected company network. You are working remotely. How do you securely connect? One common mechanism is a **VPN — Virtual Private Network**.

Conceptually:

```text

      |
      | Encrypted Connection
      v
     VPN
      |
      v
Company Network
      |
      +---- Application
      |
      +---- API
      |
      +---- Database
      |
      +---- Monitoring
```

So today a software engineer may sit hundreds or thousands of kilometres away and still work with the company's engineering environment.
