> **“A good test does not just tell us that code ran.
> A good test tells us whether the code behaved correctly.”**

# 2. First Question — What is a Unit Test?

Suppose we have an insurance application. We have a business function:

```javascript
function calculatePremium(sumAssured, rate) {
    return sumAssured * rate;
}
```

For example:

```text
Sum Assured = ₹10,00,000
Rate        = 0.02

Premium = ₹10,00,000 × 0.02
        = ₹20,000
```

We want to verify that our function produces the correct result. So we write:

```javascript
test("should calculate premium correctly", () => {

    const result = calculatePremium(1000000, 0.02);

    expect(result).toBe(20000);

});
```

This is a **unit test**.
 

# 3. Think Like a Tester

Imagine Ravi Sir asks:

> **Ravi Sir:** Student, if I give ₹10 lakh sum assured and a rate of 2%, what should the premium be?

> **Student:** ₹20,000.

> **Ravi Sir:** Good. Now let's ask the computer the same question.

```javascript
const result = calculatePremium(1000000, 0.02);
```

Now we need to verify:

```text
Actual Result    = ₹20,000
Expected Result  = ₹20,000
```

This verification is called an **assertion**.

# 4. Three Important Jest Concepts

When learning Jest, remember these three concepts:

```text
                Jest Unit Test
                      │
          ┌───────────┼───────────┐
          │           │           │
       describe()   test()     expect()
          │           │           │
       Grouping     Testing    Assertion
```

### `describe()`

Used to **group related tests**.

### `test()`

Defines an **individual test case**.

### `expect()`

Checks whether the **actual result matches the expected result**.

 

# 5. What is `describe()`?

Syntax:

```javascript
describe("group name", () => {

    // tests

});
```

Example:

```javascript
describe("Premium Calculation", () => {

    test("should calculate premium", () => {
        // test
    });

    test("should reject negative premium", () => {
        // test
    });

});
```

Here:

```javascript
describe("Premium Calculation", ...)
```

does not represent an individual test.

It creates a **logical group**.

Think of it as a folder:

```text
Premium Calculation
│
├── should calculate premium
├── should reject negative premium
└── should handle zero premium
```
 

# 6. Does `describe()` Execute a Test?

No.

This is an important concept.

```javascript
describe("Premium Calculation", () => {

});
```

There is no actual test here.

The actual tests are:

```javascript
test("should calculate premium", () => {

});
```

Therefore:

```text
describe()
     ↓
Organizes tests

test()
     ↓
Defines test

expect()
     ↓
Verifies result
```

 

# 7. Why Do Tests Work Without `describe()`?

This is perfectly valid Jest code:

```javascript
test("should calculate premium", () => {

    const result = 10000;

    expect(result).toBe(10000);

});
```

It does not require `describe()`. Jest can execute the test directly. You can write:

```javascript
test(...)
test(...)
test(...)
```

without any `describe()`.
 

# 8. Then Why Use `describe()`?

Because a real application contains many business functionalities. For our insurance application:

```text
Insurance Application
│
├── Premium Calculation
│   ├── Calculate premium
│   ├── Validate premium
│   └── Apply discount
│
├── Policy Eligibility
│   ├── Validate age
│   ├── Validate income
│   └── Validate policy type
│
├── Claim Approval
│   ├── Validate claim
│   ├── Check policy status
│   └── Approve claim
│
└── Nominee Validation
    ├── Validate nominee
    └── Validate nominee age
```

We can represent this structure in Jest:

```javascript
describe("Premium Calculation", () => {

    test("should calculate premium", () => {
        // ...
    });

    test("should validate premium", () => {
        // ...
    });

});

describe("Policy Eligibility", () => {

    test("should validate customer age", () => {
        // ...
    });

});

describe("Claim Approval", () => {

    test("should approve valid claim", () => {
        // ...
    });

});
```

Now our test report becomes meaningful.

  

# 9. What is `test()`?

`test()` represents an individual test case.

Syntax:

```javascript
test("test description", () => {

    // Arrange
    // Act
    // Assert

});
```

Example:

```javascript
test("should calculate premium correctly", () => {

    const result = calculatePremium(1000000, 0.02);

    expect(result).toBe(20000);

});
```

The first parameter:

```javascript
"should calculate premium correctly"
```

is the **test description**.

The second parameter:

```javascript
() => {
    ...
}
```

contains the actual test logic.

 

# 10. `test()` and `it()`

Jest supports both:

```javascript
test("should calculate premium", () => {
});
```

and:

```javascript
it("should calculate premium", () => {
});
```

Both are commonly used.

For beginners, we can use:

```javascript
test()
```

because it clearly communicates: “This is a test.”

 

# 11. What is an Assertion?

Suppose we have:

```javascript
const actual = calculatePremium(1000000, 0.02);
```

We expect:

```text
Expected = 20000
```

We need to ask:

> Is actual equal to expected?

That verification is an **assertion**.

In Jest:

```javascript
expect(actual).toBe(expected);
```

Example:

```javascript
expect(actual).toBe(20000);
```
 

# 12. Understanding `expect()`

Consider:

```javascript
expect(result).toBe(20000);
```

Break it into three parts:

```text
expect(result)
      │
      │
      └── Actual value

.toBe(20000)
     │
     │
     └── Expected value
```

So:

```javascript
expect(result).toBe(20000);
```

means: “I expect `result` to be 20,000.”

 
# 13. Jest Matchers

Jest calls its assertion methods **matchers**.

Examples:

```javascript
toBe()
toEqual()
toBeTruthy()
toBeFalsy()
toBeNull()
toBeDefined()
toBeGreaterThan()
toBeLessThan()
toContain()
toThrow()
```

Think:

```text
expect()
   │
   └── Matcher
          │
          ├── toBe()
          ├── toEqual()
          ├── toContain()
          ├── toThrow()
          └── ...
```
 

# 14. `toBe()`

Used mainly for primitive values and exact equality.

Example:

```javascript
test("premium should be 20000", () => {

    const premium = 20000;

    expect(premium).toBe(20000);

});
```

Another example:

```javascript
test("customer age should be 30", () => {

    const age = 30;

    expect(age).toBe(30);

});
```
 

# 15. `toEqual()`

`toEqual()` is commonly used for objects and arrays.

Example:

```javascript
const customer = {
    id: 101,
    name: "Amit",
    age: 30
};
```

Test:

```javascript
test("customer should be correct", () => {

    expect(customer).toEqual({
        id: 101,
        name: "Amit",
        age: 30
    });

});
```

For objects, prefer:

```javascript
toEqual()
```

when you want to compare their contents.

 

# 16. `toBeGreaterThan()`

Used when the actual value should be greater than a value.

Example:

```javascript
test("premium should be greater than zero", () => {

    const premium = 25000;

    expect(premium).toBeGreaterThan(0);

});
```

Business rule:

```text
Premium > 0
```
 

# 17. `toBeLessThan()`

Example:

```javascript
test("customer age should be less than 100", () => {

    const age = 45;

    expect(age).toBeLessThan(100);

});
```

Business rule:

```text
Age < 100
```
 
# 18. `toBeTruthy()`

Used when a value should be considered true.

Example:

```javascript
test("policy should be active", () => {

    const active = true;

    expect(active).toBeTruthy();

});
```

# 19. `toBeFalsy()`

Example:

```javascript
test("policy should not be active", () => {

    const active = false;

    expect(active).toBeFalsy();

});
```

# 20. `toBeNull()`

Example:

```javascript
test("customer should not have nominee initially", () => {

    const nominee = null;

    expect(nominee).toBeNull();

});
```
 
# 21. `toBeDefined()`

Used to check that a value is not `undefined`.

```javascript
test("policy number should be defined", () => {

    const policyNumber = "POL1001";

    expect(policyNumber).toBeDefined();

});
```

 
# 22. `toContain()`

Useful for arrays and strings. Example:

```javascript
test("insurance product should contain life plan", () => {

    const products = [
        "Life Protection Plan",
        "Child Future Plan",
        "Retirement Plan"
    ];

    expect(products).toContain("Life Protection Plan");

});
```
 

# 23. Testing Exceptions with `toThrow()`

Suppose our business function is:

```javascript
function calculatePremium(premium) {

    if (premium <= 0) {
        throw new Error("Premium must be greater than zero");
    }

    return premium;
}
```

We can test the exception:

```javascript
test("should reject zero premium", () => {

    expect(() => {
        calculatePremium(0);
    }).toThrow("Premium must be greater than zero");

});
```

Notice something important:

```javascript
expect(() => {
    calculatePremium(0);
})
```

We pass a **function** to `expect()`. Why? Because we want Jest to execute the function and verify that it throws an exception.

# 24. Complete Insurance Example

Let's create a simple insurance business function.

```javascript
function calculatePremium(sumAssured, rate) {

    if (sumAssured <= 0) {
        throw new Error("Sum assured must be greater than zero");
    }

    if (rate <= 0) {
        throw new Error("Rate must be greater than zero");
    }

    return sumAssured * rate;
}
```

Now write tests.

```javascript
describe("Premium Calculation", () => {

    test("should calculate premium correctly", () => {

        const result = calculatePremium(1000000, 0.02);

        expect(result).toBe(20000);

    });

    test("premium should be greater than zero", () => {

        const result = calculatePremium(500000, 0.02);

        expect(result).toBeGreaterThan(0);

    });

    test("should reject zero sum assured", () => {

        expect(() => {
            calculatePremium(0, 0.02);
        }).toThrow("Sum assured must be greater than zero");

    });

    test("should reject zero rate", () => {

        expect(() => {
            calculatePremium(1000000, 0);
        }).toThrow("Rate must be greater than zero");

    });

});
```

# 25. Understand the Test Structure

The complete test has three levels:

```text
describe()
│
│   "Premium Calculation"
│
├── test()
│   │
│   └── expect()
│
├── test()
│   │
│   └── expect()
│
├── test()
│   │
│   └── expect()
│
└── test()
        │
        └── expect()
```

Remember:

```text
describe()
    = Test Group

test()
    = Test Case

expect()
    = Assertion

matcher
    = Rule used by assertion
```

# 26. The AAA Pattern

A professional unit test often follows:

```text
AAA

Arrange
   ↓
Act
   ↓
Assert
```

### Arrange

Prepare input:

```javascript
const sumAssured = 1000000;
const rate = 0.02;
```

### Act

Execute the business function:

```javascript
const result = calculatePremium(sumAssured, rate);
```

### Assert

Verify the result:

```javascript
expect(result).toBe(20000);
```

Complete:

```javascript
test("should calculate premium correctly", () => {

    // Arrange
    const sumAssured = 1000000;
    const rate = 0.02;

    // Act
    const result = calculatePremium(sumAssured, rate);

    // Assert
    expect(result).toBe(20000);

});
```

# 27. Test Case vs Assertion

This distinction is very important.

### Test Case

```javascript
test("should calculate premium correctly", () => {
    ...
});
```

The entire block is the **test case**.

### Assertion

```javascript
expect(result).toBe(20000);
```

This is the **assertion** inside the test.

Therefore:

```text
Test Case
   │
   ├── Arrange
   │
   ├── Act
   │
   └── Assert
          │
          └── expect()
```

 

# 28. Multiple Assertions in One Test

You can have multiple assertions:

```javascript
test("customer should be valid", () => {

    const customer = {
        name: "Amit",
        age: 30,
        active: true
    };

    expect(customer.name).toBe("Amit");
    expect(customer.age).toBe(30);
    expect(customer.active).toBe(true);

});
```

However, keep tests focused. A test should ideally answer one clear business question.
 

# 29. Business-Oriented Test Naming

Avoid meaningless test names:

```javascript
test("test1", () => {
});
```

Prefer:

```javascript
test("should calculate premium for valid sum assured", () => {
});
```

Even better:

```javascript
test("should reject premium when sum assured is zero", () => {
});
```

A good test name should tell us:

```text
What is being tested? + Under what condition? + What should happen?
```

# 30. Common Jest Assertions

| Matcher             | Purpose                   | Example                                   |
| ------------------- | ------------------------- | ----------------------------------------- |
| `toBe()`            | Exact primitive value     | `expect(age).toBe(30)`                    |
| `toEqual()`         | Object/array contents     | `expect(customer).toEqual(obj)`           |
| `toBeTruthy()`      | Value is truthy           | `expect(active).toBeTruthy()`             |
| `toBeFalsy()`       | Value is falsy            | `expect(active).toBeFalsy()`              |
| `toBeNull()`        | Value is null             | `expect(value).toBeNull()`                |
| `toBeDefined()`     | Value exists              | `expect(id).toBeDefined()`                |
| `toBeGreaterThan()` | Greater than              | `expect(premium).toBeGreaterThan(0)`      |
| `toBeLessThan()`    | Less than                 | `expect(age).toBeLessThan(100)`           |
| `toContain()`       | Contains item             | `expect(products).toContain("Life Plan")` |
| `toThrow()`         | Function throws exception | `expect(fn).toThrow()`                    |

 

# 31. A Simple Mental Model

Remember this analogy:

> **`describe()` is the classroom.**
> **`test()` is the question given to the student.**
> **`expect()` is the answer checking mechanism.**

For example:

```text
Classroom
   │
   └── Premium Calculation
          │
          ├── Question 1
          │      └── Is premium ₹20,000?
          │
          ├── Question 2
          │      └── Is premium greater than zero?
          │
          └── Question 3
                 └── Does invalid input throw an error?
```

In Jest:

```javascript
describe("Premium Calculation", () => {

    test("valid premium", () => {
        expect(result).toBe(20000);
    });

    test("premium should be positive", () => {
        expect(result).toBeGreaterThan(0);
    });

    test("invalid premium should throw error", () => {
        expect(() => calculatePremium(0, 0.02))
            .toThrow();
    });

});
```
