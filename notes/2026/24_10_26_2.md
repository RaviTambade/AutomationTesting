# Transflower Mentor: What is Chromium?

Chromium is an open-source web browser project that provides the foundation for browsers such as Google Chrome.

Think of Chromium as the engine that helps a browser open websites, display HTML, execute JavaScript, apply CSS, and respond to user interactions.

## 1. Understand it through an analogy
 
 
Chromium = Browser engine and browser project

The technology that powers much of the browser experience.

 
Google Chrome = Complete browser product

Uses Chromium technologies and adds Google's product features and services.

The analogy is not exact, but it helps distinguish the underlying browser technology from the complete browser product.

Other browsers, including Microsoft Edge, also use Chromium as their foundation.

## 2. How Chromium works with Playwright

When you write a browser automation test using Node.js and TypeScript, Playwright can launch Chromium and control it programmatically.

1. Your TypeScript test :`title.spec.ts`
2. Playwright : Navigates, clicks, types and asserts
3. Chromium browser : Loads and renders the website
4. Web application: HTML + CSS + JavaScript

For example:

```
import { test, expect } from '@playwright/test';

test('Check website title', async ({ page }) => {
    await page.goto('https://example.com');

    await expect(page).toHaveTitle('Example Domain');
});
```

What happens?

1. Playwright launches a Chromium browser using its configured browser fixture.
2. Chromium opens `https://example.com`.
3. The browser loads and renders the page.
4. Playwright reads the page title.
5. The assertion passes if the title matches `Example Domain`.

## 3. How do we install Chromium?

When you set up Playwright, execute:

```
npx playwright install chromium
```

This downloads the Chromium browser build supported by your installed Playwright version.

Run your test:

```
npx playwright test tests/title.spec.ts
```

To see the browser window:

```
npx playwright test tests/title.spec.ts --headed
```

By default, browser tests commonly run in headless mode, meaning the browser operates without displaying a visible window.

## 4. Chromium vs. Chrome

| Feature                            | Chromium                                                 | Google Chrome                                    |
| ---------------------------------- | -------------------------------------------------------- | ------------------------------------------------ |
| Nature                             | Open-source browser project                              | Complete browser product                         |
| Maintained by                      | Open-source community and contributors, including Google | Google                                           |
| Browser engine                     | Blink, with Chromium's browser components                | Blink, based on Chromium                         |
| Playwright testing                 | Supported directly                                       | Also supported by Playwright                     |
| Additional Google product features | Not necessarily included                                 | Includes additional Google features and services |

One important detail: Playwright's installed Chromium build is not necessarily identical to the Chromium version bundled into Google Chrome.

## 5. Mentor's takeaway

When learning browser automation, remember these three roles:

- Node.js runs your JavaScript or TypeScript test code.
- Playwright controls the browser and verifies expected behavior.
- Chromium provides the browser environment in which your website runs.

As a Transflower learner, your next experiment is to run the same title-checking test in Chromium, Firefox, and WebKit. This helps you discover whether your application behaves consistently across different browser engines.

# Lab 2: Cross-browser testing

Objective: Verify that `https://example.com` displays the correct page title in three different browser engines.

## 1. Understand the architecture

```
          TRANSFLOWER LEARNING
       PLAYWRIGHT ARCHITECTURE
================================================

       +-----------------------------+
       |       TypeScript Test       |
       |                             |
       |        title.spec.ts        |
       |                             |
       |  test() + expect()          |
       +--------------+--------------+
                      |
                      v
       +-----------------------------+
       |     Playwright Test Runner  |
       |                             |
       |  - Discover tests           |
       |  - Execute tests            |
       |  - Manage browser sessions  |
       |  - Report PASS / FAIL       |
       +--------------+--------------+
                      |
          +-----------+-----------+
          |           |           |
          v           v           v
 +----------------+ +----------------+ +----------------+
 |    Chromium    | |    Firefox     | |     WebKit     |
 |                | |                | |                |
 | Browser Engine | | Browser Engine | | Browser Engine |
 +-------+--------+ +-------+--------+ +-------+--------+
         |                  |                  |
         v                  v                  v
 +----------------+ +----------------+ +----------------+
 |     Blink      | |     Gecko      | | WebKit Engine  |
 | Rendering      | | Rendering      | | Rendering      |
 | JavaScript V8  | | JavaScript     | | JavaScript     |
 |                | | SpiderMonkey   | | JavaScriptCore |
 +----------------+ +----------------+ +----------------+
         |                  |                  |
         v                  v                  v
 +----------------+ +----------------+ +----------------+
 | Chrome / Edge  | | Firefox        | | Safari         |
 | Compatibility  | | Compatibility  | | Compatibility  |
 +----------------+ +----------------+ +----------------+
```

### Mentor explanation

- TypeScript Test (`title.spec.ts`): Defines browser actions and assertions.
- Playwright Test Runner: Discovers tests, launches browsers, executes tests, and reports results.
- Chromium → Blink: Chromium uses the Blink rendering engine. Chrome and Microsoft Edge are Chromium-based browsers.
- Firefox → Gecko: Firefox uses the Gecko rendering engine.
- WebKit → WebKit: WebKit is the engine associated with Safari.

Important distinction: Chromium, Firefox, and WebKit are the browser targets Playwright automates. Blink, Gecko, and WebKit are browser engines that render web content. Playwright's WebKit build is not identical to the full Safari browser.

Remember: One test, three browser engines, broader cross-browser confidence.


## 2. Install the browsers

Run this command in your project terminal:

```
npx playwright install chromium firefox webkit
```

## 3. Configure Playwright

Open `playwright.config.ts`. If you created the project with `npm init playwright@latest`, replace its contents with this minimal configuration:

```

import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
    testDir: './tests',

    projects: [
        {
            name: 'chromium',
            use: { ...devices['Desktop Chrome'] },
        },
        {
            name: 'firefox',
            use: { ...devices['Desktop Firefox'] },
        },
        {
            name: 'webkit',
            use: { ...devices['Desktop Safari'] },
        },
    ],
});

```

## 4. Write the test

Create `tests/title.spec.ts`:

```

import { test, expect } from '@playwright/test';

test('Verify website title', async ({ page }) => {
    await page.goto('https://example.com');

    await expect(page).toHaveTitle('Example Domain');

    console.log('Website title verified successfully');
});

```

Notice that the test code does not change for different browsers. Playwright selects the browser according to the configured project.

## 5. Execute the test suite

Run all three browser projects:

```
npx playwright test tests/title.spec.ts
```

Run only Chromium:

```
npx playwright test --project=chromium
```

Run only Firefox:

```
npx playwright test --project=firefox
```

Run only WebKit:

```
npx playwright test --project=webkit
```

Expected result, assuming all browsers launch and the website is reachable:

```
Running 3 tests using 3 workers

  ✓ [chromium] Verify website title
  ✓ [firefox] Verify website title
  ✓ [webkit] Verify website title

  3 passed
```

This is an illustrative report, not a result from an actual test execution.

# Transflower Hands-on Lab 3: Playwright Locators and Button-Click Automation

Node.js + TypeScript + Playwright | TAP Software Testing

In our previous labs, we opened a website and checked its title across Chromium, Firefox and WebKit.

Now let's take the next step: find an element on a webpage, click a button, and verify the result.

## 1. Understand the testing flow

Open the website

`page.goto()`

Find the button

`page.getByRole()`

Click the button

`.click()`

Verify the result

`expect()`

## 2. Create a simple webpage

To understand browser automation, let's create our own small webpage rather than depend on an external website.

Inside your project, create `demo.html`.

```

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Transflower Learning</title>
</head>
<body>
    <h1>Welcome to Transflower Learning</h1>

    <button id="startButton">Start Learning</button>

    <p id="message"></p>

    <script>
        document
            .getElementById('startButton')
            .addEventListener('click', () => {
                document.getElementById('message').textContent =
                    'Your learning journey has started!';
            });
    </script>
</body>
</html>

```

When a user clicks the button, JavaScript updates the paragraph with a confirmation message.

## 3. Write the Playwright test

Create `tests/button.spec.ts`.

```

import { test, expect } from '@playwright/test';
import path from 'node:path';
import { pathToFileURL } from 'node:url';

test('Click Start Learning button', async ({ page }) => {
    // Arrange: Open our demo webpage
    const fileUrl = pathToFileURL(
        path.resolve('demo.html')
    ).href;

    await page.goto(fileUrl);

    // Act: Find and click the button
    await page.getByRole('button', {
        name: 'Start Learning'
    }).click();

    // Assert: Verify the expected message
    await expect(
        page.locator('#message')
    ).toHaveText(
        'Your learning journey has started!'
    );
});

```

The `pathToFileURL()` approach converts the local HTML file path into a valid file URL. This lab needs no web server.

## 4. Understand locators

A locator tells Playwright which element to find on the page.

| Locator         | Example                                                | Purpose                                    |
| --------------- | ------------------------------------------------------ | ------------------------------------------ |
| Accessible role | `page.getByRole('button', { name: 'Start Learning' })` | Finds a button by role and accessible name |
| Label           | `page.getByLabel('Username')`                          | Finds a form field by its label            |
| Placeholder     | `page.getByPlaceholder('Enter username')`              | Finds a field by placeholder               |
| Text            | `page.getByText('Welcome')`                            | Finds matching text                        |
| CSS selector    | `page.locator('#message')`                             | Finds an element by CSS selector           |

Mentor tip: Prefer user-facing locators such as roles and labels when practical. They make tests easier to read and often more resilient to implementation changes.

## 5. Run the test

From the project root:

```
npx playwright test tests/button.spec.ts
```

To see Chromium performing the click:

```
npx playwright test tests/button.spec.ts --headed --project=chromium
```

Expected result, if the test executes successfully:

```
✓ Click Start Learning button

1 passed
```

This is an illustrative result, not a report from an actual execution.

# Transflower Hands-on Lab 4: Login Form Automation

Node.js + TypeScript + Playwright | TAP Automation Testing

In our previous lab, we clicked a button and verified the result. Now let's automate a real-world scenario: enter a username and password, click Login, and verify the dashboard.

## 1. Understand the test scenario

1. Open Login Page
2. Enter Username and Password
3. Click Login
4. Verify Dashboard

## 2. Create the login webpage

Create `login.html` in your project root.

```

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Transflower Login</title>
</head>
<body>
    <h1>Student Login</h1>

    <form id="loginForm">
        <label for="username">Username</label>
        <input id="username" name="username" required />

        <br /><br />

        <label for="password">Password</label>
        <input
            id="password"
            name="password"
            type="password"
            required
        />

        <br /><br />

        <button type="submit">Login</button>
    </form>

    <p id="message" role="alert"></p>

    <script>
        document.getElementById('loginForm')
            .addEventListener('submit', function (event) {
                event.preventDefault();

                const username =
                    document.getElementById('username').value;
                const password =
                    document.getElementById('password').value;

                if (
                    username === 'valid_student' &&
                    password === 'demo_password'
                ) {
                    document.body.innerHTML = `
                        <h1>Dashboard</h1>
                        <p>Welcome to Transflower Learning!</p>
                    `;
                    document.title = 'Transflower Dashboard';
                } else {
                    document.getElementById('message').textContent =
                        'Invalid credentials';
                }
            });
    </script>
</body>
</html>

```

This is a learning demo only. It checks hard-coded credentials in browser-side JavaScript and is not suitable for real authentication.

## 3. Write the Playwright test

Create `tests/login.spec.ts`.

```

import { test, expect } from '@playwright/test';
import path from 'node:path';
import { pathToFileURL } from 'node:url';

test('Valid login opens dashboard', async ({ page }) => {
    const loginUrl = pathToFileURL(
        path.resolve('login.html')
    ).href;

    // Arrange: Open the login page
    await page.goto(loginUrl);

    // Act: Enter credentials
    await page.getByLabel('Username')
        .fill('valid_student');

    await page.getByLabel('Password')
        .fill('demo_password');

    // Act: Click Login
    await page.getByRole('button', {
        name: 'Login'
    }).click();

    // Assert: Verify successful login
    await expect(
        page.getByRole('heading', {
            name: 'Dashboard'
        })
    ).toBeVisible();

    await expect(page).toHaveTitle(
        'Transflower Dashboard'
    );
});

test('Invalid login displays an error', async ({ page }) => {
    const loginUrl = pathToFileURL(
        path.resolve('login.html')
    ).href;

    await page.goto(loginUrl);

    await page.getByLabel('Username')
        .fill('valid_student');

    await page.getByLabel('Password')
        .fill('wrong_password');

    await page.getByRole('button', {
        name: 'Login'
    }).click();

    await expect(page.getByRole('alert'))
        .toHaveText('Invalid credentials');

    await expect(
        page.getByRole('heading', {
            name: 'Student Login'
        })
    ).toBeVisible();
});

```

## 4. Execute the tests

Run both tests from the project root:

```
npx playwright test tests/login.spec.ts
```

Run with a visible Chromium browser:

```
npx playwright test tests/login.spec.ts --headed --project=chromium
```

Expected report if both tests pass:

```
✓ Valid login opens dashboard
✓ Invalid login displays an error

2 passed
```

This is an illustrative expected result, not an actual execution report.

## 5. Understand what you tested

| Testing concept  | What the test verifies                         |
| ---------------- | ---------------------------------------------- |
| Form interaction | Username and password can be entered           |
| UI action        | Login button submits the form                  |
| Positive test    | Valid demo credentials display the dashboard   |
| Negative test    | Invalid credentials display an error           |
| Assertion        | The expected heading, message and title appear |
